# WebUI 使用指南

本指南适用于 SAYACODE 3.2。WebUI 是本机 `sayacode` 的默认入口。若仍在使用 2.x，请升级到 3.2 以使用这里介绍的页面。

## 启动

在项目目录执行：

```bash
sayacode --workspace .
```

CLI 打印 `SAYACODE WebUI: http://127.0.0.1:<端口>/#token=...`，并尝试打开浏览器。需要自己打开地址时，运行 `sayacode --no-open`。`sayacode --port 8765` 固定端口；默认端口由系统分配。`--workspace` 指定启动时加入列表的本机目录。

启动地址含一次浏览器登录令牌，不宜分享或粘贴到公开日志。页面建立会话后会从地址栏移除令牌。关闭标签页不停止正在执行的任务；要关闭服务，在启动它的终端中中断进程。

## 首次配置模型

1. 点击输入框底部的设置按钮，在唯一的设置窗口中进入“全局 → 模型连接”。
2. 点击“添加模型”，输入配置名、接口协议、接口地址、API Key、模型 ID、上下文长度和最大输出 token 数。
3. 保存后可用“测试”检查文本、工具调用和流式能力，再点“设为当前模型”。

协议支持 OpenAI Chat Completions、OpenAI Responses API、Anthropic Messages、Gemini Native generateContent 和 Ollama Native Chat。接口地址必须与所选协议相符；模型名称不会改变协议。初次添加时填写 API Key；若端点明确无需认证，勾选“此端点无需认证”。编辑已有配置时留空保留原密钥，勾选无认证会清除原密钥。密钥输入不会在模型列表中回显。测试会访问真实端点。

无密钥配置不会读取环境变量中的真实密钥。部分官方模型适配器仍要求非空密钥参数，因而可能向端点发送非秘密占位认证头；若端点拒绝任意认证头，需要允许该占位值。

模型尚未配置时，本机页面、工作区和设置仍能打开；发送需要模型执行的任务前应先启用一份配置。

## 工作区、会话和任务

左侧“工作区”展示已登记的本机目录。点击加号，再点“浏览本机目录”，可逐级选择目录；也可直接粘贴绝对路径。添加可选显示名称后即可加入项目。点击工作区后，下面显示该工作区的会话；可新建、重命名或删除会话。删除前会检查活动运行、子 Agent 和未清理的工作树。

在中间输入框描述目标，按 Enter 发送；Shift+Enter 换行。输入框有内容时右下角是发送键；输入框为空且会话树仍在运行时，同一位置显示停止键；已停止时显示恢复键。若选中的子 Agent 已停止，先恢复主会话，再恢复该子 Agent。Agent 运行中仍可输入：发送后先进入输入框旁的持久队列，队列中的每条消息可编辑、删除或点“直接发送”。直接发送会把同一条消息交给下一安全模型步骤，不中止当前模型请求或工具调用。等待审批或已经停止的子 Agent 收到新消息时先保留在队列；处理审批或显式恢复后才继续投递。切换会话或关闭页面不会因为浏览器连接变化而中止宿主中的运行。

对话在用户输入与 Agent 回答之间显示紧凑的过程行：运行时持续显示当前操作与耗时，展开后可查看并发工具的各项状态、参数和结果；完成后过程行留在原位并折叠。上翻阅读历史时不会强制跳回底部，可用“回到最新”返回。独立的“运行轨迹”保留按轮次分组、调用起止合并及类别筛选，供详细诊断。待办区域显示 SAYA 的原生计划；选择子 Agent 时也可查看其待办。运行轨迹和任务列表按线程标识、标题与颜色区分。

输入框左下角的加号提供添加文件、压缩上下文和选择 Skill。当前附件支持 UTF-8 文本文件，由本机服务暂存，并作为当前消息的文件路径引用；文件内容不会在上传时直接发送给模型，图片、PDF 等二进制格式暂不支持。压缩和 Skill 激活作用于所选线程，运行或审批尚未完成时暂不可执行。底部模型与信任控件也只作用于当前线程；新会话创建时采用全局默认模型，之后可随时切换。子 Agent 创建时采用父线程派发时的模型，之后也可单独切换。

## 审批与信任

输入框底部的信任档位只影响当前选中的主 Agent 或子 Agent 线程。全局默认信任档在唯一的设置窗口中配置，只影响新建主会话；子 Agent 复制派发时父线程的档位。

| 档位 | 使用建议与行为 |
| --- | --- |
| 只读 | 探查代码；不可使用写文件、Shell 和未知 MCP 工具 |
| 询问 | 有副作用的操作逐项等待人工决定 |
| 工作区内自动改动 | 文件工具可全局读取，只在当前工作区内自动改动；Shell 和其他副作用工具逐次询问 |
| 完全信任 | 直接执行当前用户有权限执行的工具调用 |

待批准操作出现在右侧“审批”。选择相应的主会话或子 Agent，逐项查看工具与参数并选择批准或拒绝。需要时可在询问档记住本会话中完全相同的工具调用；“稍后处理”会保留暂停状态。等待审批或原图仍有待恢复步骤时不能切换信任档，须先处理原步骤；这样拒绝决定不会因切档而被忽略。继续执行时，服务器会核对当前 checkpoint，过期审批需刷新页面后重新决定。

SAYACODE 没有操作系统沙箱。工作区内自动改动档只约束内置文件工具，并在操作时重新检查路径；批准后的原生 Shell 仍以启动 CLI 的用户权限运行，可联网和改动工作区外文件。只读和工作区内自动改动线程不运行 Hook；MCP 服务器可能在连接及读取工具目录时启动，审批拦截的是之后的单次工具调用。只读档限制模型可获得的工具，但仍会更新待办、检查点及任务消息，不能隔离操作系统中的其他进程。planner/reviewer 子 Agent 不能调用文件写入、Shell 或外部 MCP，仍可向父线程回报；builder 可写时按派发时继承的档位执行。子 Agent 使用独立 worktree 时，它的“当前工作区”指该 worktree。

## 子 Agent 与代码交付

右侧“协作”展示 SAYA 与子 Agent 的关系图或列表。主 Agent 可以自行派发；也可以点“创建子 Agent”，选择 builder、planner 或 reviewer，填写任务和可选标题。“使用独立 Git worktree”按次选择。点击任务卡会打开该子 Agent 的线程；在其输入框发送内容即可追问。

子 Agent 可以和主 Agent 同时运行，子 Agent 自己有消息、工具轨迹、待办与审批。任务卡提供运行中停止、停止后恢复和审批入口。主会话的停止按钮会请求整棵子 Agent 任务树停止，并阻止完成通知再次自动唤醒主 Agent；已保存的检查点和未处理交付仍会保留。主会话即使没有待继续的主任务，也可手动恢复到空闲状态；子 Agent 仍保持停止，需要逐个显式恢复。子 Agent 完成后的结果进入父会话 Inbox，父 Agent 空闲时可以被通知唤醒继续处理。

采用独立 worktree 的 builder 完成后，在右侧“变更”中选择任务，先“查看差异”，再确认“应用到主工作区”。应用不会自动提交。共享工作区模式直接编辑原目录，没有单独的交付差异。worktree 只覆盖该树内的文件变化，无法捕获 Agent 对其他绝对路径的改动。

## 设置与扩展

输入框底部的设置按钮打开唯一完整设置窗口。窗口按“全局、工作区、当前线程”标明作用域：全局默认模型、默认信任、语言及运行参数在全局；MCP、项目诊断与项目资源在工作区；当前模型、信任、Skill 及检查点操作在当前线程。自动唤醒保护控制通知循环，**不是**模型调用轮次或工具次数上限。

界面语言可选中文、English 或跟随浏览器；切换后页面文案即时更新，不改变已保存的会话消息。

- **MCP**：添加或移除用户/项目服务器，信任或撤销项目级配置，并重载当前工作区的连接。项目 `.mcp.json` 需显式信任。
- **Skill**：列出当前工作区可用的项目与用户 Skill，并为当前选中线程启用。项目位置为 `.agents/skills/<名称>/SKILL.md`，用户位置为 `SAYACODE_HOME/skills/<名称>/SKILL.md`。
- **记忆**：开启或关闭长期记忆，决定是否向新会话提供旧记忆及是否自动整理；可手动保存、搜索、修正、确认和遗忘用户/项目记录。自动学习需要额外模型请求。
- **诊断**：查看当前工作区 Git 状态、项目结构、符号搜索和运行检查。
- **会话与运行**：查看当前线程的检查点、运行追踪与工具目录；空闲时手动聚焦摘要或选择检查点回退。回退会要求再次确认，且不会撤销文件和 Git 操作。这里也可清除本会话记住的批准、覆盖当前会话记忆设置，以及查看、信任、重载工作区 Hook。

## 无浏览器任务

单次任务和诊断继续由 CLI 提供：

```bash
sayacode -p "检查最近改动" --workspace . --output-format text
sayacode -p "总结测试失败" --output-format jsonl
sayacode --doctor --json
```

`-p -` 从标准输入读取任务；`--output-format` 支持 `text`、`json`、`jsonl`。无头任务需要人工审批时保存暂停点并返回退出码 `3`；成功 `0`，运行失败 `1`，配置/参数错误 `2`，用户中断 `130`。`--no-open` 和 `--port` 只适用于 Web 服务，不与 `-p` 或 `--doctor` 混用。

架构与状态边界见 [架构说明](architecture.md)，项目首页见 [README](../README.md)。
