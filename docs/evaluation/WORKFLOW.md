# SAYACODE 调优迭代工作流（WORKFLOW）

> 本文件定义**怎么调优、怎么量化、怎么判定**的闭环流程。配套主台账 `README.md`。
> 最后更新：2026-10-29

## 0. 四条原则

1. **护栏先行**：结果指标变好但过程护栏变差（改测试、回归破坏、空转）→ 一律不采纳。
2. **免费杠杆优先**：同批数据多算指标（免费）> 加重复（中）> 加题量（贵）。
3. **三层金字塔**：能秒级反馈就别跑小时级。
4. **一切入台账**：每个实验在 `README.md` 台账追加一行（含 n、效应量、强度）。

## 1. 闭环流程（PDCA）

```
①观察失败画像 ─→ ②提出假设 ─→ ③L1诊断(秒~分) ─→ ④L2回归(分钟)
      ↑                                              │
      │                                       护栏是否恶化?
      │                                        ├─是→ 回退/改方向
      │                                        └─否→ ⑤L3正式配对(小时)
      │                                              │
      └──── ⑥判定(效应量+CI) ── 入库/回退 ←─────────┘
```

### ① 观察：从哪找改进点（用 `analyze_eval.py` 输出）
- **partial credit 最低**的题（差得最多的能力面）
- **护栏异常**：改既有测试次数 >0、空转（patch=0）、重复读同一文件多
- **效率异常**：步数远超同类、token 曲线陡增

### ② 假设：一次只改一个变量
示例：`改上下文清理参数 → 预期 partial↑ 且 token↓`

### ③ L1 诊断（秒~分，`evals/run`）
- 场景：`evals/scenarios/*.jsonl`（协作、上下文等能力切片）
- 目的：验证机制是否被触发（如协作是否派发、上下文是否压缩）
- 门槛：功能正确 + 过程指标符合预期

### ④ L2 回归（分钟，`run_regression.py`）
- 回归集：`C:\sb\pipelines\regression-set.json`（5–10 题，**含历史失败题**）
- 目的：改动是否打破已知能过的题、是否修好已知失败题
- 门槛：**无回归破坏**（原本 PASS 的仍 PASS）

### ⑤ L3 正式（小时，`run_pipeline.py` + A/B）
- 题量：120–180 题（分层抽样）或 HARD-51 40 题
- 重复：2 次（抵消同题方差）
- 设计：**配对**（同题同重复跑基线与候选）
- 工具：`run_pipeline.py`（跑批）→ `analyze_eval.py`（指标）→ `compare_ab.py`（配对统计）

### ⑥ 判定（Go / No-Go）
见第 3 节判定表。

## 2. 指标体系（三层）

| 层 | 指标 | 工具 |
|---|---|---|
| **结果** | pass@1、**partial credit**、pass@k、**pass^k（一致率）**、回归破坏率 | `analyze_eval.py` |
| **过程** | 步数、重复读文件、**改既有测试次数**、**空转率(patch=0)**、首次编辑前探索步数、API 失败 | `analyze_eval.py` |
| **效率** | token/成功、时长/成功 | `analyze_eval.py` |

## 3. 判定规则（Go / No-Go）

| 检查 | Go 条件 | No-Go 信号 |
|---|---|---|
| **护栏（一票否决）** | 改既有测试次数 = 0；回归破坏 = 0；空转率 ≤ 基线 | 任一恶化 |
| **结果效应** | risk difference ≥ +15pp 且 95%CI 不跨 0（McNemar p<0.05） | CI 跨 0 或为负 |
| **效率** | token/成功 恶化 < 20% | 恶化 ≥ 20% |
| **稳定性** | pass^k 不下降 | pass^k 下降（一过一败加剧） |

> 对个人开发者：**先过护栏，再看效应量**。护栏不过，效应量再好也回退。

## 4. 证据强度分级（写台账时必标）

| 强度 | 条件 |
|---|---|
| 强 | 护栏全绿 + n≥5 重复 或 效应量≥20pp 且 CI 稳定 |
| 中 | n=2–4 或方向一致但方差可见 |
| 弱 | n=1 或仅单场景触发 |

## 5. 实验登记（自动化）

每次 L3 跑完，把 `analyze_eval.py` 与 `compare_ab.py` 的输出追加到 `README.md` 台账，字段：日期 / 实验 / 数据集 / n / 结果指标 / 护栏 / 强度 / 文档链接。

## 6. 节奏（个人开发者版）

| 频率 | 层 | 成本 |
|---|---|---|
| 每次改动 | L1 + L2 | 分钟级，几乎零 |
| 每周/里程碑 | L3（120–180×2）| 小时级 |
| 发版前 | L3 全量 + 报告 | 小时级 |

## 7. 工具链

| 用途 | 命令 |
|---|---|
| L1 能力诊断 | `python -m evals.run run --catalog evals/scenarios/xxx.jsonl --variants team ...` |
| L2 回归 | `python C:\sb\pipelines\run_regression.py` |
| L3 跑批 | `python C:\sb\pipelines\run_pipeline.py --split holdout --repeats 2 ...` |
| 指标计算 | `python C:\sb\pipelines\analyze_eval.py <jobs目录>` |
| 配对比对 | `python C:\sb\pipelines\compare_ab.py <A jobs> <B jobs>` |
| 对账 | `python C:\sb\pipelines\reconcile.py` |

## 8. 成本/时间护栏

- L2 单次 ≤ 15 分钟；L3 单次 ≤ 预算上限（¥50）。
- 出现空转（patch=0 且步数>50）或 token 陡增 → 早停该题，记异常。
- 题量只在里程碑加，不为单次改动跑 L3。
